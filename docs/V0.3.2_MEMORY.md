# V0.3.2 项目学习记忆：实现与验证

日期：2026-09-14。版本 0.3.2，SQLite schema v4。

## 实际数据流

主动截图或发送追问 → 当前 Project／Source／Session 与输入绑定 → ContextManager 使用本地 FTS 和概念别名 → 当前项目待解决记忆的确定性筛选 → 受限 ContextPackage → format_reading → 官方 CodexProvider → 服务确认 turn/start → 侧栏显示本次记忆用量 → 完成回答和发送快照一次保存 → 后续请求重新检索。

未确认提交前显示“本次请求尚未确认发送”，不能把连接队列或候选当作已使用。服务确认提交或收到对应回答事件后才展示用量。“使用”表示请求已携带该背景，不保证模型一定引用或理解正确。

ReadingContextSnapshot 脱离当前 UI 和数据库可变状态，保存请求、项目、资料、会话和最终选定的记忆。正文、概念、状态及资料名／页码章节与模型收到的记忆字段一致；本地 ID 只用于归属和来源回溯，不发送给模型。模型不获得数据库访问能力。

旧阅读结果的 context_snapshot 为空；回看显示“旧回答未记录所用记忆”，不查询当前候选冒充历史。新结果即使对应记忆后来编辑、解决或删除，仍展示原发送快照。失败、取消或不完整输出不保存为成功。

## 复用与最小迁移

继续使用 memories、concepts／concept_aliases、memory_screenshots、FTS 索引、ScreenshotStore、ReadingStore 和现有上下文与模型接口，没有建立第二套记忆系统。

schema v4 只增加：

- memories.status：pending／resolved，旧数据默认 pending，不改变原正文或 memory_type。旧笔记的“待解决”表示尚未人工标记解决，不能视为系统对掌握程度的判断。
- memories.reading_result_id：引用阅读结果，ON DELETE SET NULL。
- memories.source_snapshot：保留已知资料名、用户填写的页码／章节及原阅读 ID。
- reading_results.context_snapshot：完成请求的记忆使用记录。

Database 原迁移框架继续先在线备份到 data/backups，再逐版本事务迁移；失败回滚当前迁移。每个应用数据库连接及备份连接启用外键。旧 schema 更高时仍拒绝降级。此次未运行正式 data/study.db 的升级；测试在独立临时数据库验证 v1/v2/v3 数据兼容。正式数据在下一次启动时自动备份升级。

阅读结果继续最多 60 条，临时图片清理仍可级联删除结果。被用户保存的记忆只失去已清理阅读结果的活引用，原 ID 与已知来源说明仍保留；正文不受影响。关联记忆的截图沿用原机制提升为保留状态；删除记忆不会将图片降级或删除。取舍是显式保留的图片需用户自行管理完整数据备份，暂不新增永久图片删除图库。

## 检索与控制

实际侧栏构建显式启用 strict_project_memory；FTSMemoryRetriever 原接口默认行为保留用于 V0.1 程序接口兼容。所有现行侧栏阅读和手动交接都走严格模式，不注入 global／user scope 的长期记忆；原记录仍在数据库中。固定的语言、翻译风格等设置继续提供。

检索依据为当前文字、问题、用户指定概念和 Topic。先过滤当前项目与 pending，再从原 FTS／概念检索取得最多 20 个候选，经过额外可靠匹配门槛：关联概念匹配，或正文中两个非通用英文词、一个至少 10 字符的非通用英文词、一个共享中文三字片段。英文别名使用完整词边界。此方法确定、可测试，但不是语义理解，仍可能漏检或误匹配；无文字线索不会拿最近记忆凑数。

手动指定同项目待解决记忆先于自动匹配，重复去重；已解决、已删除、外项目 ID 全部排除。最多 5 条，连同本地来源字段的序列化总长最多 6000 字符；超过剩余预算的整条记忆跳过，不截断正文。保存正文上限仍为 2000 字符。

“本次使用项目记忆”影响后续新请求，默认勾选，本次运行内保留选择，重启后恢复默认。指定概念／记忆沿用同一项目与资料的后续请求，窗口内显示提示，可清空；切换项目或资料会清空指定。这些操作本身不发送任何内容。

普通追问最多保留两轮问答。某轮回答引用的记忆若已关闭、解决、修改、删除或未进入本次选择，剔除该轮回答正文，保留原问题，避免借旧回答间接重新发送停用记忆。来源消失导致快照变化时也采用同样保守处理。因此某些“为什么”追问需要用户补充具体问题。

概念和别名沿用原有共享术语表。编辑框可更换关联概念、填写新概念或添加别名；显示现有别名。别名是共享术语，不是用户掌握状态；本阶段不提供共享别名删除。记忆正文始终按项目检索。

## 手动端到端验收（本轮未执行真实模型／外部阅读器）

下面步骤会在用户主动发送时使用订阅额度。可先在隔离目录运行：

~~~powershell
cd D:\aStudyCopilot
.\.venv\Scripts\python.exe -m studycopilot --home D:\StudyCopilotMemoryCheck
~~~

1. 顶部新建“模电验证 A”，添加资料“教材样本”；启用自动翻译后，在外部阅读器按界面实际快捷键框选包含 gm 的段落，检查侧栏项目／资料及真实回答。
2. 输入“为什么跨导的单位是西门子？”并发送；完成后点“记住这个疑问”。确认正文可编辑，关联概念 transconductance，添加别名 gm／跨导，填已知页码，状态待解决，明确保存。
3. 关闭应用，再用同一命令启动；重新选择 A 和资料，在“项目记忆”中查看正文、状态、时间和来源，修改一处正文。
4. 再截图并问“gm 的单位怎么推导？”；检查已用数量，展开查看发送时正文与来源。生成期间编辑该记忆或修改追问草稿，旧回答的使用记录应保持原值。
5. 问明确无关的问题，检查“本次未使用历史学习记忆”。纯截图没有文字线索时，先在“指定概念／记忆”中填写 gm 或选中疑问，再进行主动截图；指定动作本身不应启动请求。
6. 关闭“本次使用项目记忆”后发送追问，检查未使用提示。重新开启，标记已解决，再发送相关问题，默认也不携带；重新打开可恢复相关检索。
7. 删除记忆，确认阅读记录仍能在本次学习的最近截图中回看，旧回答仍显示其发送时快照，新请求不再携带。
8. 新建“模电验证 B”，提出同名概念问题；不能带入 A 的疑问。A 请求生成期间切换 B，旧流式文字、完成结果、使用信息不能出现在 B。
9. 从记忆查看现存截图或原问答。自动化测试已覆盖清理与缺图；如需人工核对缺图，仅在隔离目录关闭应用后移动其测试 PNG，再打开查看缺失提示，切勿操作正式数据。
10. 检查 Alt+Q、Alt+A、Alt+Shift+Q 及冲突回退、取消截图、剪贴板恢复与窗口切换。不同阅读器、多屏、高 DPI、保护内容仍需具体机器实测。

本轮未调用真实模型、未重新登录用户账号、未消耗或购买／兑换额度；未验证本阶段在真实阅读器、多显示器及服务更新后的端到端表现。界面用量证明携带了背景，不能证明模型回答准确引用；简单检索不支持语义相似检索、OCR 或跨项目记忆。
