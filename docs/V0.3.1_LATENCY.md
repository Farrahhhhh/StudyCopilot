# V0.3.1 延迟修复

日期：2026-09-11。针对用户反馈“小块目录翻译完成需要 29 秒”。

## 找到的问题与修改

1. V0.3.0 中途换图会终止整个 App Server 进程。用户本机日志显示，第二张截图重连从 20:57:35.164 到 20:57:42.547，约 7.4 秒。V0.3.1 对已有 turn ID 的请求发送官方 turn/interrupt 和 thread/unsubscribe，保留认证与模型连接。尚未拿到可中断 ID 时仍采用安全重启。
2. 模型请求重复携带详细交接说明、空字段、窗口标题、图片路径和内部 ID。新的阅读请求只附任务与已有的必要文字、项目／资料名、相关术语／记忆和有限问答。完整本地 ContextPackage 与备用手动交接保持原样。
3. 目录直接逐项翻译，不要求重复抄写全部英文。仍保留必要的英文术语、公式、编号和单位，不删减待翻译条目。
4. 修复“顶部已连接，正文仍显示正在连接”。现在区分连接、准备请求、等待首段、生成中，并显示已等待秒数；超过 10 秒明确提示服务响应较慢。日志仅增加阶段耗时，不记录图片内容、译文或提示。
5. 按服务公布的能力选择可用的较低推理强度。已验证模型目前支持 low，未强行发送不支持的 none/minimal，也未换模型或付费服务档位。

## 同一合成目录的对照

使用 scripts/benchmark_reading.py，自制一张 CMOS 工艺目录图，通过同一已连接进程、同一 gpt-5.6-luna 模型交替使用旧／新请求。只发送合成图，不补发用户旧截图。

证据：test-results/latency-e403634c/results.json。

| 请求 | 首段秒 | 完成秒 |
| --- | ---: | ---: |
| 旧请求，第 1 次 | 12.578 | 13.906 |
| 精简请求，第 1 次 | 4.016 | 7.047 |
| 旧请求，第 2 次 | 7.078 | 12.031 |
| 精简请求，第 2 次 | 7.766 | 11.563 |
| 中途换图后，精简请求 | 8.422 | 10.437 |

最后一项在生成中主动替换请求，确认进程 PID 保持不变，新图翻译成功。所有回答保留目录的章节编号与条目。

这些是少量顺序样本，存在网络、排队和缓存影响，不能据此保证稳定提速比例或所有实际图片都在固定秒数内完成。它也不是用户那张原始图片的前后对照。用户报告的 29 秒仍是有效的实际体验，不能用合成测试掩盖。

## 回归与边界

137 项测试通过，结果保存于 test-results/v031-final.xml。新增覆盖紧凑请求不携带内部路径／ID、必要学习上下文保留、中断后连接保留、无 turn ID 时安全重启、旧请求消息隔离和等待阶段／计时更新。

数据库仍为 schema v3，没有数据迁移或删除。官方登录方式与订阅额度策略保持不变。停止首先隔离本地晚到结果并发出中断，不保证远端在同一瞬间停止处理／消耗额度。

本次优化减少不必要的本地连接开销和输入长度；模型服务排队及视觉推理本身的等待仍可能波动。

最终侧栏复测（2026-09-11）：test-results/v03-live-18225f44。自制教材图首段 6.938 秒、完成 8.125 秒；沿用当前图追问首段 4.188 秒、完成 10.329 秒。两条结果均显示并写入隔离数据库，已检查原生窗口截图。该样本与前述目录测试分开记录。
